     5→# 💍 The Ring - Skills Library for AI Agents
     6→
     7→**Proven engineering practices, enforced through skills.**
     8→
     9→Ring is a comprehensive skills library and workflow system for AI agents that transforms how AI assistants approach software development. Currently implemented as a **Claude Code plugin marketplace** with **4 active plugins**, **76 skills**, and **33 agents** (see `.claude-plugin/marketplace.json` for current versions), the skills themselves are agent-agnostic and can be used with any AI agent system. Ring provides battle-tested patterns, mandatory workflows, and systematic approaches across the entire software delivery value chain.
    10→
    11→## ✨ Why Ring?
    12→
    13→Without Ring, AI assistants often:
    14→
    15→- Skip tests and jump straight to implementation
    16→- Make changes without understanding root causes
    17→- Claim tasks are complete without verification
    18→- Forget to check for existing solutions
    19→- Repeat known mistakes
    20→
    21→Ring solves this by:
    22→
    23→- **Enforcing proven workflows** - Test-driven development, systematic debugging, proper planning
    24→- **Providing 76 specialized skills** (23 core + 35 dev-team + 14 product planning + 4 technical writing)
    25→- **33 specialized agents** - 2 planning/analysis + 24 developer/reviewer + 4 product research + 3 technical writing
    26→- **Automating skill discovery** - Skills load automatically at session start
    27→- **Preventing common failures** - Built-in anti-patterns and mandatory checklists
    28→
    29→## 🧭 Project Identity
    30→
    31→**Ring is Lerian-first, open-source-friendly.** Design decisions prioritize the Lerian engineering team's daily needs while keeping the architecture clean and reusable for external adoption. This means:
    32→
    33→- **Lerian-specific skills stay active** — Internal integrations and domain-specific workflows remain in the marketplace because the team uses them
    34→- **The architecture is universal** — Skills, agents, and the plugin system work with any codebase or team
    35→- **Archival is usage-driven** — Skills are archived when they stop being used, not because they're "too specific"

   112→## 🖥️ Supported Platforms
   113→
   114→Ring works across multiple AI development platforms:
   115→
   116→| Platform        | Native manifest        | Symlink installer       | Status             |
   117→| --------------- | ---------------------- | ----------------------- | ------------------ |
   118→| **Claude Code** | ✅ marketplace.json    | ✅ `--claude`           | Source of truth    |
   119→| **Codex**       | ✅ `.codex-plugin/`    | ✅ `--codex` (built)    | Both paths work    |
   120→| **OpenCode**    | ✅ `.opencode/`        | ✅ `--opencode` (built) | Both paths work    |
   121→| **Cursor**      | ✅ `.cursor-plugin/`   | ❌ not in installer     | Native only        |
   122→| **Factory AI**  | ❌                     | ✅ `--factory`          | Installer only     |
   123→
   124→**Two install mechanisms:**
   125→
   126→- **Native manifest** — the harness installs Ring directly from this repo via its own package manager (`opencode.json`, Cursor plugin marketplace, Codex plugin manifest). No local build step, no manual symlink work. Best for end users and CI.
   127→- **Symlink installer** (`ring-install.sh`) — symlinks from your local harness config dir into a cloned Ring repo. For Codex/OpenCode, the installer builds a transformed tree at `.ring-build/` first (namespace + frontmatter rewrites). Best for local development with hot-reload against the source tree.
   128→
   129→See the [`Native plugin install`](#native-plugin-install-per-harness) and [`Symlink installer`](#symlink-installer-local-dev) sub-sections below for usage.

   131→## 🚀 Quick Start
   132→
   133→### Native plugin install (per harness)
   134→
   135→Each Ring plugin ships native manifests for Claude Code, Codex, Cursor, and OpenCode. The harness installs the plugin directly from this repo via its own package manager — no transformation step, no local installer.
   136→
   137→| Harness         | Mechanism                                | Per-plugin entry points |
   138→| --------------- | ---------------------------------------- | ----------------------- |
   139→| **Claude Code** | `.claude-plugin/marketplace.json` (root) | All 4 plugins enumerated in one marketplace file |
   140→| **Codex**       | `<plugin>/.codex-plugin/plugin.json`     | [default](default/.codex-plugin/plugin.json) · [dev-team](dev-team/.codex-plugin/plugin.json) · [pm-team](pm-team/.codex-plugin/plugin.json) · [tw-team](tw-team/.codex-plugin/plugin.json) |
   141→| **Cursor**      | `<plugin>/.cursor-plugin/plugin.json`    | [default](default/.cursor-plugin/plugin.json) · [dev-team](dev-team/.cursor-plugin/plugin.json) · [pm-team](pm-team/.cursor-plugin/plugin.json) · [tw-team](tw-team/.cursor-plugin/plugin.json) |
   142→| **OpenCode**    | `<plugin>/.opencode/` (INSTALL + JS plugin) | [default](default/.opencode/INSTALL.md) · [dev-team](dev-team/.opencode/INSTALL.md) · [pm-team](pm-team/.opencode/INSTALL.md) · [tw-team](tw-team/.opencode/INSTALL.md) |
   143→
   144→**`ring-default` is the foundation plugin** — install it alongside any other Ring plugin since it provides the `using-ring` bootstrap that orients agent behavior. Example for OpenCode:
   145→
   146→```json
   147→{
   148→  "plugin": [
   149→    "ring-default@git+https://github.com/lerianstudio/ring.git#main",
   150→    "ring-dev-team@git+https://github.com/lerianstudio/ring.git#main"
   151→  ]
   152→}
   153→```
   154→
   155→Each harness's INSTALL.md (for OpenCode) or `plugin.json` (for Codex/Cursor) carries the exact install command for that platform.
   156→
   157→### Symlink installer (local dev)
   158→
   159→`ring-install.sh` symlinks your harness's local config dir into this cloned Ring repo. For Codex and OpenCode, it first builds a transformed tree at `.ring-build/` (namespace + frontmatter rewrites required by those tools).
   160→
   161→**Supported targets:** Claude Code, Factory AI, OpenCode, Codex.
   162→**Not supported by the installer:** Cursor (use the [native plugin install above](#native-plugin-install-per-harness)).
   163→
   164→```bash
   165→# Clone the repo
   166→git clone https://github.com/lerianstudio/ring.git ~/ring
   167→cd ~/ring
   168→
   169→# Interactive menu (lets you pick targets)
   170→bash ring-install.sh
   171→
   172→# Or target specific harnesses without the prompt:
   173→bash ring-install.sh --claude               # Claude Code (per-file symlinks)
   174→bash ring-install.sh --factory              # Factory AI (per-file symlinks)
   175→bash ring-install.sh --opencode             # OpenCode (builds .ring-build/opencode/ first)
   176→bash ring-install.sh --codex                # Codex    (builds .ring-build/codex/ first)
   177→bash ring-install.sh --all                  # All four supported targets
   178→```
   179→
   180→#### Installer subcommands
   181→
   182→```bash
   183→bash ring-install.sh install --opencode --codex   # install symlinks for selected targets
   184→bash ring-install.sh remove                        # remove all Ring symlinks
   185→bash ring-install.sh build                         # rebuild .ring-build/{opencode,codex} only
   186→bash ring-install.sh clean                         # remove .ring-build/ outputs
   187→bash ring-install.sh doctor                        # verify install + build outputs
   188→bash ring-install.sh all --all -y                  # clean + build + install for all targets, no prompt
   189→```
   190→
   191→**Flags:** `--yes` / `-y` (skip confirmation), `--dry-run` (preview without changes), `--force` (back up non-symlink collisions), `--verbose`.

   422→### Code Review (Parallel, 9 Defaults + Conditional Specialists)
   423→
   424→```
   425→User: "Review my authentication implementation"
   426→Claude: Dispatching all 9 default reviewers plus triggered conditional specialists in parallel...
   427→        [Launches ring:code-reviewer, ring:logic-reviewer, ring:security-reviewer,
   428→         ring:test-reviewer, ring:nil-reviewer,
   429→         ring:dead-code-reviewer, ring:perf-reviewer, ring:tenancy-reviewer,
   430→         ring:commons-reviewer simultaneously]
   431→        Conditional specialists trigger only when the diff touches their stack:
   432→        lib-observability, lib-systemplane, or lib-streaming.
   433→
   434→        Code reviewer: PASS. Clean architecture, good tests.
   435→        Business reviewer: FAIL. Missing password reset flow (HIGH severity).
   436→        Security reviewer: FAIL. JWT secret hardcoded (CRITICAL severity).
   437→        Test reviewer: PASS. Good coverage, assertions well-structured.
   438→        Nil-safety reviewer: PASS. No unguarded nil dereferences found.
   439→        Performance reviewer: PASS. No hotspots or goroutine leaks found.
   440→        Multi-tenant reviewer: PASS. No multi-tenant code in scope.
   441→        lib-commons reviewer: PASS. Correct shared-library usage, no reinvented wheels detected.
   442→
   443→        Aggregating issues by severity:
   444→        - CRITICAL: JWT secret hardcoded in auth.ts:42
   445→        - HIGH: Password reset flow missing from requirements
   446→
   447→        Review report complete. No files changed by reviewers.
   448→        Fixes require a separate implementation step, then a new review run.
   449→```
   450→
   451→**Key benefits:**
   452→
   453→- **All reviewers run simultaneously** (not sequential)
   454→- **Comprehensive** - Get all feedback at once, easier to prioritize
   455→- **Report-only boundary** - Reviewers report findings; remediation is a separate step
   456→- **Specialized lanes** - Each reviewer owns a clear domain to avoid duplicate slop

   518→## 🤝 Contributing
   519→
   520→### Adding a New Skill
   521→
   522→**For core Ring skills:**
   523→
   524→1. **Create the skill directory**
   525→
   526→   ```bash
   527→   mkdir default/skills/your-skill-name
   528→   ```
   529→
   530→2. **Write SKILL.md with frontmatter**
   531→
   532→   ```yaml
   533→   ---
   534→   name: ring:your-skill-name
   535→   description: Single paragraph (≤500 chars target, 1,536 cap). States WHAT the skill does, WHEN to invoke, and WHEN to skip.
   536→   ---
   537→
   538→   # Your Skill Name
   539→
   540→   ## When to use
   541→   - Specific condition that mandates this skill
   542→   - Another trigger condition
   543→
   544→   ## Skip when
   545→   - When NOT to use → alternative skill
   546→   - Another exclusion
   547→   ```
   548→
   549→   **Schema fields:**
   550→
   551→   - **Required:** `name` (must use `ring:` prefix), `description`
   552→   - **Optional:** `argument-hint`, `allowed-tools`, `model`, `disable-model-invocation`, `user-invocable`, `paths`
   553→   - Trigger / skip / sequence / related content lives in body H2 sections (`## When to use`, `## Skip when`, `## Sequence`, `## Related`). See [docs/FRONTMATTER_SCHEMA.md](docs/FRONTMATTER_SCHEMA.md) for the canonical schema.
   554→
   555→3. **Update documentation**
   556→
   557→   - Skills auto-load via `default/hooks/generate-skills-ref.py`
   558→   - Test with session start hook
   559→
   560→4. **Submit PR**
   561→   ```bash
   562→   git checkout -b feat/your-skill-name
   563→   git add default/skills/your-skill-name
   564→   git commit -m "feat(skills): add your-skill-name for X"
   565→   gh pr create
   566→   ```
   567→
   568→**For product/team-specific skills:**
   569→
   570→1. **Create plugin structure**
   571→
   572→   ```bash
   573→   mkdir -p product-xyz/{skills,agents,hooks,lib}
   574→   ```
   575→
   576→2. **Register in marketplace**
   577→   Edit `.claude-plugin/marketplace.json`:
   578→
   579→   ```json
   580→   {
   581→     "name": "ring-product-xyz",
   582→     "description": "Product XYZ specific skills",
   583→     "version": "0.1.0",
   584→     "source": "./product-xyz",
   585→     "homepage": "https://github.com/lerianstudio/ring/tree/product-xyz"
   586→   }
   587→   ```
   588→
   589→3. **Follow core plugin structure**
   590→   - Use same layout as `default/`
   591→   - Create `product-xyz/hooks/hooks.json` for initialization
   592→   - Add skills to `product-xyz/skills/`
   593→
   594→### Skill Quality Standards
   595→
   596→- **Mandatory sections**: When to use, How to use, Anti-patterns
   597→- **Include checklists**: TodoWrite-compatible task lists
   598→- **Evidence-based**: Require verification before claims
   599→- **Battle-tested**: Based on real-world experience
   600→- **Clear triggers**: Unambiguous "when to use" conditions
